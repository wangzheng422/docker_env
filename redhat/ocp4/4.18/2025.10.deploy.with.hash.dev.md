# deployment with hash in annotation

some secret contains tls cert, after it rotation, some pods will restart, we will analyze it, and give suggestions on how to deal with it.

We can see `metrics-client-certs` is refereced in Prometheuses CR object, which is handled by prometheus-operator. below is the key logic in prometheus-operator, it will calculate the hash value, and update the stateful set CR, which will trigger the pod restart.

- https://github.com/openshift/prometheus-operator/blob/release-4.18/pkg/prometheus/server/operator.go#L825-L838
```go
		newSSetInputHash, err := createSSetInputHash(*p, c.config, ruleConfigMapNames, tlsAssets, existingStatefulSet.Spec)
		if err != nil {
			return err
		}

		sset, err := makeStatefulSet(
			ssetName,
			p,
			c.config,
			cg,
			ruleConfigMapNames,
			newSSetInputHash,
			int32(shard),
			tlsAssets)
```

and the hash value is set by this logic

- https://github.com/openshift/prometheus-operator/blob/release-4.18/pkg/operator/factory.go#L111-L126
```go
// InputHashAnnotationName is the name of the annotation used to store the
// operator's computed hash value.
const InputHashAnnotationName = "prometheus-operator-input-hash"

// WithInputHashAnnotation records the given hash string in the object's
// annotations.
func WithInputHashAnnotation(h string) ObjectOption {
	return func(o metav1.Object) {
		a := o.GetAnnotations()
		if a == nil {
			a = map[string]string{}
		}
		a[InputHashAnnotationName] = h
		o.SetAnnotations(a)
	}
}
```

The whole logic is, if promethus operator find some config changes, not limited to tls rotation, it will restart promethus to re-read the config and start again. the restart is by-design, and act as it purpose.

based on the analyze, the pod restart logic is highly bind into source code, and it varired among operator/component.

## recommend

instead of search all of the ocp component/deployment which will restart automatically, it is better isolate cpu cores running openshift component from application, so the ocp compoent/deployment restart will not affact application, this is the design pattern / goals of openshift.

If you think openshift compnent restart break your business, you can raise case/RFE to redhat, and ask for enhance on service continues.

# check deployment with hash in annotation

if you still want to search deployment which will affect by secret rotation, let's try to do this step by step.

first, let's check the anntation name end with `-input-hash`.

```bash
#!/bin/bash

# 脚本功能：
# 在 OpenShift 集群的所有命名空间中，查找所有在其 Pod 模板中
# 包含以 "-input-hash" 结尾的注解键的 Deployment、StatefulSet、
# DaemonSet 和 DeploymentConfig 资源。

# 定义要检查的 Kubernetes/OpenShift 资源类型
RESOURCE_TYPES=("deployment" "statefulset" "daemonset" "deploymentconfig")

echo "正在全局搜索包含 '*-input-hash' 注解的工作负载..."
echo "================================================================================"

# 内部函数，用于处理所有资源并以制表符分隔的格式输出
find_resources() {
  # 首先打印表头
  printf "NAMESPACE\tKIND\tNAME\n"

  # 遍历每一种资源类型
  for KIND in "${RESOURCE_TYPES[@]}"; do
    # 使用 oc 命令获取所有命名空间下的当前类型的所有资源，并以 JSON 格式输出。
    # 使用 jq 进行解析和过滤，输出以制表符分隔。
    oc get "$KIND" --all-namespaces -o json 2>/dev/null | jq -r '
     .items[] |
      select(
       .metadata.annotations and 
        (.metadata.annotations | keys | any(endswith("-input-hash")))
      ) |
      "\(.metadata.namespace)\t\(.kind)\t\(.metadata.name)"
    '
  done
}

# 调用函数，并将输出通过管道传递给 column 命令进行格式化
# -t 表示创建一个表格
# -s $'\t' 表示使用制表符作为分隔符
find_resources | column -t -s $'\t'

echo "================================================================================"
echo "搜索完成。"
```

#!/bin/bash

# Define the resource types to scan

# Internal function to process resources and output in tab-separated format

  # Print the header first
  printf "NAMESPACE\tKIND\tNAME\n"

  # Loop through each resource type
  for KIND in "${RESOURCE_TYPES[@]}"; do
    # Get all resources of the current kind from all namespaces in JSON format.
    # Use jq to parse, filter, and format the output.
    oc get "$KIND" --all-namespaces -o json 2>/dev/null | jq -r '
      .items[] |

        .metadata.annotations and
        # --- This is the key change ---
        # 1. Get all annotation values
        # 2. Check if ANY value matches the regex for a long hex string
        (.metadata.annotations | values | any(test("^[a-f0-9]{16,}$")))
      ) |
      # Format the output for matching resources
      "\(.metadata.namespace)\t\(.kind)\t\(.metadata.name)"
    '
  done
}

# Call the function and pipe the output to the column command for formatting
# -t creates a table
