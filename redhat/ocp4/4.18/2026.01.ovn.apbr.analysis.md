# AdminPolicyBasedExternalRoute 工作原理分析

## 概述

AdminPolicyBasedExternalRoute (APBR) 是 OpenShift OVN-Kubernetes 中用于实现基于策略的外部路由的功能。它允许管理员为特定的命名空间或 Pod 配置自定义的下一跳路由,实现流量的精细化控制。

## 配置示例

根据你提供的配置:

```yaml
spec:
  from:
    namespaceSelector:
      matchLabels:
        kubernetes.io/metadata.name: ns-blue
  nextHops:
    static:
      - bfdEnabled: false
        ip: 10.132.2.10
```

这个配置的含义是:
- **from**: 选择源命名空间 `ns-blue` 中的所有 Pod
- **nextHops.static**: 指定静态下一跳为 `10.132.2.10` (这是 ns-blue-gateway Pod 的 IP)
- **bfdEnabled**: 禁用 BFD (Bidirectional Forwarding Detection) 检测

## OVN 实现机制

### 1. 路由表配置

在 OVN 配置中,APBR 会创建以下关键规则:

#### 路由规则 (lr_in_ip_routing - table 15)

```
priority=256, match=(reg7 == 0 && ip4.src == 10.135.0.41/32), 
action=(ip.ttl--; flags.loopback = 1; reg8[0..15] = 1; reg8[16..31] = 1; next;)
```

**解释:**
- `priority=256`: 高优先级路由规则
- `match=(reg7 == 0 && ip4.src == 10.135.0.41/32)`: 匹配源 IP 为 10.135.0.41 的流量 (business-app Pod)
- `reg8[0..15] = 1; reg8[16..31] = 1`: 设置寄存器标记,表示需要进行 ECMP 路由处理

#### ECMP 路由处理 (lr_in_ip_routing_ecmp - table 16)

```
priority=100, match=(reg8[0..15] == 1 && reg8[16..31] == 1), 
action=(reg0 = 10.132.2.10; reg5 = 192.168.99.27; eth.src = 00:50:56:8e:2a:52; 
        outport = "rtoe-GR_worker-02-demo"; reg9[9] = 1; next;)
```

**解释:**
- `match=(reg8[0..15] == 1 && reg8[16..31] == 1)`: 匹配前面设置的标记
- `reg0 = 10.132.2.10`: 设置下一跳 IP 为 10.132.2.10 (gateway Pod)
- `reg5 = 192.168.99.27`: 设置网关 IP
- `outport = "rtoe-GR_worker-02-demo"`: 设置出口端口为 worker-02 的网关路由器端口
- `reg9[9] = 1`: 标记为 IPv4 流量

### 2. ECMP 状态跟踪 (lr_in_ecmp_stateful - table 11)

```
priority=100, match=(inport == "rtoe-GR_worker-02-demo" && ip4.dst == 10.135.0.41 && (ct.new || ct.est)), 
action=(ct_commit { ct_label.ecmp_reply_eth = eth.src; ct_mark.ecmp_reply_port = 2;}; next;)
```

**解释:**
- 对于返回流量,记录源 MAC 地址和端口信息
- 确保双向流量使用相同的路径 (会话亲和性)

### 3. 返回流量处理

```
priority=10300, match=(ct_mark.ecmp_reply_port == 2 && reg7 == 0 && ip4.src == 10.135.0.41/32), 
action=(ip.ttl--; flags.loopback = 1; eth.src = 00:50:56:8e:2a:52; reg5 = 192.168.99.27; 
        outport = "rtoe-GR_worker-02-demo"; next;)
```

**解释:**
- 根据连接跟踪标记,确保返回流量走相同的路径
- 维持流量的对称性

## 工作流程

### 出站流量 (ns-blue business-app -> 外部)

1. **源 IP 匹配**: business-app Pod (10.135.0.41) 发出的流量被 table 15 的规则匹配
2. **设置标记**: 设置 `reg8[0..15] = 1` 和 `reg8[16..31] = 1`
3. **ECMP 路由**: table 16 根据标记,将下一跳设置为 10.132.2.10 (gateway Pod)
4. **ARP 解析**: 解析 gateway Pod 的 MAC 地址
5. **转发**: 流量被转发到 gateway Pod
6. **SNAT**: Gateway Pod 进行 SNAT,将源 IP 转换为外部 IP
7. **出口**: 流量从物理网络接口发出

### 入站流量 (外部 -> ns-blue business-app)

1. **连接跟踪**: 根据 `ct_mark.ecmp_reply_port` 识别返回流量
2. **路径选择**: 使用相同的路径返回 (通过 gateway Pod)
3. **DNAT**: 恢复原始目标 IP
4. **转发**: 流量被转发回 business-app Pod

## 关键数据结构

### 寄存器用途

- **reg0**: 下一跳 IP 地址
- **reg5**: 网关 IP 地址
- **reg7**: 路由策略标记
- **reg8[0..15]**: ECMP 组标识
- **reg8[16..31]**: ECMP 成员标识
- **reg9[9]**: IPv4/IPv6 标记 (1=IPv4, 0=IPv6)
- **ct_mark.ecmp_reply_port**: 连接跟踪标记,记录回复端口
- **ct_label.ecmp_reply_eth**: 连接跟踪标记,记录回复 MAC 地址

### 网络拓扑

```
business-app (10.135.0.41) 
    ↓
[OVN Logical Router - table 15: 匹配源 IP]
    ↓
[OVN Logical Router - table 16: ECMP 路由,设置下一跳为 10.132.2.10]
    ↓
gateway Pod (10.132.2.10)
    ↓
[SNAT: 10.135.0.41 -> 192.168.99.27]
    ↓
外部网络
```

## 总结

AdminPolicyBasedExternalRoute 的核心原理是:

1. **策略路由**: 通过 OVN Logical Router Policy 实现基于源 IP 的路由决策
2. **ECMP 机制**: 利用 OVN 的 ECMP (Equal-Cost Multi-Path) 功能实现灵活的下一跳选择
3. **连接跟踪**: 使用 OVN 的连接跟踪功能确保双向流量的一致性
4. **寄存器传递**: 通过 OVN 流表中的寄存器在不同 table 之间传递路由决策信息

本质上,APBR 就是在 OVN 中配置了一系列高优先级的路由规则,这些规则会:
- 匹配特定命名空间的 Pod 流量
- 将流量重定向到指定的下一跳 (gateway Pod)
- 维护连接状态,确保返回流量走相同路径

这种实现方式完全基于 OVN 的原生功能,不需要额外的组件,性能开销很小。
