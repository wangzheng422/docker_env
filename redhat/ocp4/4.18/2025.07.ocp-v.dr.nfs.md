# OpenShift Virtualization Disaster Recovery based on storage replication solution.

In redhat solution, ocp-v do not have build-in DR solution, redhat recommend using odf's DR feature to do that. 本质上说，这是一个存储解决方案。而odf支持的后端存储方案是ceph或者ibm flash storage。如果客户使用的是dell, emc, hitachi等第三方存储方案，那么ocp-v DR方案应该怎么做呢？

我们的思路是用openshift的odap功能，备份ocp-v的meta data，包括虚拟机配置，pv/pvc配置。同时使用底层存储方案的远程备份到远端站点。当主站点出现问题，手动触发DR过程，主站点ocp-v虚拟机关机，存储设置只读。然后检查或者开启底层存储远程备份，同步pv/lun，并检查备份过程完成。然后在远端站点导入ocp-v meta data，同时对pv中的存储系统相关信息进行更新，确保pv匹配到了正确的存储lun或者目录。至此完成DR过程。

从远端站点切换回主站点的过程相同。

本文，就用nfs模拟底层存储系统，完成一个ocp-v DR的过程，先通过手动操作完成，然后把整个过程在GenAI辅助下，用ansible实现自动化。

Because we have customized NFS storage, we need to ensure CNV recognizes it.

```bash

cat << EOF > $BASE_DIR/data/install/cnv-sp.yaml
apiVersion: cdi.kubevirt.io/v1beta1
kind: StorageProfile
metadata:
  name: nfs-dynamic
spec:
  claimPropertySets:
  - accessModes:
    - ReadWriteMany
    volumeMode: Filesystem
EOF

oc apply -f $BASE_DIR/data/install/cnv-sp.yaml

```

# install oadp

<img src="imgs/2025.07.ocp-v.dr.nfs.md/2025-07-24-15-56-54.png" width="1024">

```bash

cat << EOF > $BASE_DIR/data/install/credentials-minio
[default]
aws_access_key_id = minioadmin
aws_secret_access_key = minioredhat
EOF

oc create secret generic minio-credentials \
--from-file=cloud=$BASE_DIR/data/install/credentials-minio \
-n openshift-adp

# define the oadp instance
# oc delete -f $BASE_DIR/data/install/oadp.yaml
cat << EOF > $BASE_DIR/data/install/oadp.yaml
apiVersion: oadp.openshift.io/v1alpha1
kind: DataProtectionApplication
metadata:
  name: velero-instance
  namespace: openshift-adp # OADP Operator 所在的命名空间
spec:
  # 1. 在这里定义你的 S3 存储桶信息
  backupLocations:
    - name: default
      velero:
        provider: aws # 或 gcp, azure, etc.
        default: true
        objectStorage:
          bucket: ocp
          prefix: velero # 备份将存储在桶内的 velero/ 目录下
        config:
          # 对于非AWS S3，例如MinIO，需要提供URL
          s3Url: http://192.168.99.1:9000
          region: us-east-1
        # 引用包含您的S3凭证的Secret
        credential:
          name: minio-credentials
          key: cloud
  
  # 2. 在这里配置 Velero 的核心行为和插件
  configuration:
    velero:
      # 指定要使用的插件
      defaultPlugins:
        - openshift
        - kubevirt
        - csi
        - aws
        
    # 3. 在这里配置卷快照和数据移动器 (DataMover/Kopia)
    csi:
      enable: false
    datamover:
      enable: false
EOF

oc apply -f $BASE_DIR/data/install/oadp.yaml


```
