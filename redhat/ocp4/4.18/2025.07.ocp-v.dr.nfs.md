# OpenShift Virtualization Disaster Recovery based on storage replication solution.

In redhat solution, ocp-v do not have build-in DR solution, redhat recommend using odf's DR feature to do that. 本质上说，这是一个存储解决方案。而odf支持的后端存储方案是ceph或者ibm flash storage。如果客户使用的是dell, emc, hitachi等第三方存储方案，那么ocp-v DR方案应该怎么做呢？

我们的思路是用openshift的odap功能，备份ocp-v的meta data，包括虚拟机配置，pv/pvc配置。同时使用底层存储方案的远程备份到远端站点。当主站点出现问题，手动触发DR过程，主站点ocp-v虚拟机关机，存储设置只读。然后检查或者开启底层存储远程备份，同步pv/lun，并检查备份过程完成。然后在远端站点导入ocp-v meta data，同时对pv中的存储系统相关信息进行更新，确保pv匹配到了正确的存储lun或者目录。至此完成DR过程。

从远端站点切换回主站点的过程相同。

本文，就用nfs模拟底层存储系统，完成一个ocp-v DR的过程，先通过手动操作完成，然后把整个过程在GenAI辅助下，用ansible实现自动化。

Because we have customized NFS storage, we need to ensure CNV recognizes it.

```bash

cat << EOF > $BASE_DIR/data/install/cnv-sp.yaml
apiVersion: cdi.kubevirt.io/v1beta1
kind: StorageProfile
metadata:
  name: nfs-dynamic
spec:
  claimPropertySets:
  - accessModes:
    - ReadWriteMany
    volumeMode: Filesystem
EOF

oc apply -f $BASE_DIR/data/install/cnv-sp.yaml

```
