# OVN egressip limitation workaround

## Background

customer install a ocp 4.18 on 3rd part osp, using baremetal install method. and the osp has limitation of 10 elastic ip on each node. but the security require each namespace has a dedicate egress ip, and there are 40+ namespaces. and the elastic ip pools contains different subnets, and worker node has different associated relationship with elastic ip pools subnets. current ovn does not support node selector for egressip. and only single pool of egressip is supported. so we need to implement a workaround to support this requirement.

the basic idea is to use a gateway pod for each namespace to provide egress ip for the namespace. use ovn config to route the traffic to the gateway pod for the namespace pod. and use a tool pod to monitor the gateway pod's ip, and change ovn config's next hop ip when the gateway pod restart.

## Workaround

```bash

oc create ns ns-blue

oc create ns ns-egress-infra


# 创建 SA 
oc create sa apb-syncer -n ns-egress-infra

# 1. 删除旧的局部权限
oc delete rolebinding apb-syncer-binding -n ns-egress-infra --ignore-not-found


# 2. 创建集群角色
cat <<EOF | oc apply -f -
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: apb-cluster-manager
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list", "watch"]
- apiGroups: ["k8s.ovn.org"]
  resources: ["adminpolicybasedexternalroutes"]
  verbs: ["get", "list", "watch", "patch", "update"]
EOF

# 3. 创建集群角色绑定 (将 ns-blue 里的 SA 绑定到集群角色)
cat <<EOF | oc apply -f -
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: apb-syncer-cluster-binding
subjects:
- kind: ServiceAccount
  name: apb-syncer
  namespace: ns-egress-infra
roleRef:
  kind: ClusterRole
  name: apb-cluster-manager
  apiGroup: rbac.authorization.k8s.io
EOF


oc label node worker-01-demo egress-node=ns-blue-group


cat <<EOF | oc apply -f -
apiVersion: "k8s.cni.cncf.io/v1"
kind: NetworkAttachmentDefinition
metadata:
  name: ns-blue-external-macvlan
  namespace: ns-egress-infra  # 必须和网关 Pod 在同一个 NS
spec:
  config: '{
      "cniVersion": "0.3.1",
      "type": "macvlan",
      "master": "br-ex",
      "mode": "bridge",
      "ipam": {
        "type": "static"
      }
    }'
EOF


# 创建 Gateway 专用的 SA
oc create sa gateway-sa -n ns-egress-infra

# 为该 SA 授予 privileged SCC
oc adm policy add-scc-to-user privileged -z gateway-sa -n ns-egress-infra

cat <<'EOF' | oc apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ns-blue-gateway
  namespace: ns-egress-infra
spec:
  replicas: 1 
  selector:
    matchLabels:
      app: ns-blue-gateway
  template:
    metadata:
      labels:
        app: ns-blue-gateway
      annotations:
        k8s.v1.cni.cncf.io/networks: '[
          {
            "name": "ns-blue-external-macvlan", 
            "interface": "macvlan0",
            "ips": ["192.168.99.2/24"]
          }
        ]'
    spec:
      serviceAccountName: gateway-sa
      nodeSelector:
        egress-node: ns-blue-group
      containers:
      - name: gateway
        image: registry.redhat.io/openshift4/ose-egress-router:latest
        command: ["/bin/sh", "-c"]
        args:
        - |
          # 0. 开启 IP 转发 & 关闭反向路径过滤 (rp_filter) !!! 关键 !!!
          # rp_filter=1 (Strict) 会丢弃源 IP 不符合路由表预期的包
          sysctl -w net.ipv4.ip_forward=1
          sysctl -w net.ipv4.conf.all.rp_filter=0
          sysctl -w net.ipv4.conf.default.rp_filter=0
          sysctl -w net.ipv4.conf.eth0.rp_filter=0
          sysctl -w net.ipv4.conf.macvlan0.rp_filter=0
          
          # 确保 Forward 链是 ACCEPT
          iptables -P FORWARD ACCEPT
          
          # 1. 保存 OVN 网络原本的网关
          OVN_GW=$(ip route show default | awk '/default/ {print $3}')
          
          # 2. 为 Pod 网络和 Service 网络添加路由，确保走 eth0
          #    如果您知道具体 CIDR，请替换 10.0.0.0/8 和 172.16.0.0/12
          ip route add 10.0.0.0/8 via $OVN_GW dev eth0
          ip route add 172.16.0.0/12 via $OVN_GW dev eth0
          
          # 3. 确保 macvlan0 接口已启动
          ip link set macvlan0 up
          
          # 4. 切换默认路由指向物理网关
          # 这一步非常重要，否则 Pod 里的包不知道怎么去外网
          ip route del default
          ip route add default via 192.168.99.1 dev macvlan0
          
          # 5. 设置核心 SNAT 规则
          iptables -t nat -A POSTROUTING -o macvlan0 -j SNAT --to-source 192.168.99.2
          
          # 5. 为了调试方便，加一条日志
          echo "交大版手动网关已启动！出口 IP: 192.168.99.2，物理网关: 192.168.99.1";
          
          # 6. 防止容器退出
          sleep infinity;
        securityContext:
          privileged: true
EOF

```

**Important: Disable OVN Port Security**

The OVN switch port for the gateway pod by default filters traffic that doesn't match the pod's assigned IP. Since we are routing traffic from external IPs into `eth0` for return (reply) packets, we **must** disable this security check.

```python
# 文件名: controller.py
import os
import time
import threading
from kubernetes import client, config, watch

# 配置常量
# 配置常量
NAMESPACE = "ns-blue"
GATEWAY_NAMESPACE = "ns-egress-infra"
APB_NAME = "ns-blue-route"
GATEWAY_LABEL = "app=ns-blue-gateway"
GROUP = "k8s.ovn.org"
VERSION = "v1"
PLURAL = "adminpolicybasedexternalroutes"

def get_current_gateway_ips(v1):
    """获取当前所有 Running 状态的网关 Pod IP"""
    try:
        pods = v1.list_namespaced_pod(GATEWAY_NAMESPACE, label_selector=GATEWAY_LABEL)
        return sorted([p.status.pod_ip for p in pods.items if p.status.phase == "Running" and p.status.pod_ip])
    except Exception as e:
        print(f"Error listing pods: {e}")
        return []

def reconcile_apb():
    """核心调谐逻辑：对比并强制同步"""
    config.load_incluster_config()
    v1 = client.CoreV1Api()
    api = client.CustomObjectsApi()

    # 1. 获取当前网关真实的 Pod IP 列表 (期望状态)
    desired_ips = get_current_gateway_ips(v1)
    if not desired_ips:
        print("No running gateway pods found. Skipping sync.")
        return

    desired_formatted = [{"ip": ip} for ip in desired_ips]

    try:
        # 2. 读取当前 APB 资源的实际状态
        current_apb = api.get_cluster_custom_object(GROUP, VERSION, PLURAL, APB_NAME)
        current_static_hops = current_apb.get("spec", {}).get("nextHops", {}).get("static", [])

        # 3. 幂等性检查：对比期望 IP 和 实际 IP
        # 提取当前 IP 字符串进行对比
        current_ips_str = sorted([hop["ip"] for hop in current_static_hops if "ip" in hop])
        
        if current_ips_str == desired_ips:
            # 如果完全一致，直接退出，防止触发 Watch 的死循环
            return 

        # 4. 如果不一致，执行强制修正
        print(f"Detect deviation! Desired: {desired_ips}, Current in APB: {current_ips_str}. Correcting...")
        body = {"spec": {"nextHops": {"static": desired_formatted}}}
        api.patch_cluster_custom_object(GROUP, VERSION, PLURAL, APB_NAME, body)
        print("APB Successfully enforced.")

    except Exception as e:
        print(f"Reconciliation failed: {e}")

def watch_pods():
    """监听 Pod 变化"""
    v1 = client.CoreV1Api()
    w = watch.Watch()
    print("Started watching Pods...")
    for event in w.stream(v1.list_namespaced_pod, namespace=GATEWAY_NAMESPACE, label_selector=GATEWAY_LABEL):
        # 只要 Pod 状态有变（新增、删除、重启），执行调谐
        reconcile_apb()

def watch_apb():
    """监听 APB 资源变化（防止人为手动修改）"""
    api = client.CustomObjectsApi()
    w = watch.Watch()
    print("Started watching APB Resource...")
    # 注意：watch 的资源必须对应其 plural 名称
    for event in w.stream(api.list_cluster_custom_object, GROUP, VERSION, PLURAL):
        resource = event.get('object', {})
        if resource.get('metadata', {}).get('name') == APB_NAME:
            # 只要 APB 被修改（不管是人为还是程序），执行调谐
            # reconcile_apb 内部的对比逻辑会防止死循环
            reconcile_apb()

if __name__ == "__main__":
    config.load_incluster_config()
    
    # 启动时先执行一次强制同步
    reconcile_apb()

    # 使用多线程同时监听两类资源
    t1 = threading.Thread(target=watch_pods)
    t2 = threading.Thread(target=watch_apb)

    t1.start()
    t2.start()

    t1.join()
    t2.join()
```

### Analysis Matrix

| eth0 (In) | macvlan0 (Out) | macvlan0 (In - Reply) | eth0 (Out - Reply) | Potential Cause |
| :--- | :--- | :--- | :--- | :--- |
| No  | - | - | - | **OVN Issue**: APB Route is not steering traffic to the gateway pod. Check APB resource and OVN traces. |
| Yes | No | - | - | **Forwarding Issue**: `iptables` FORWARD dropped, or Kernel `ip_forward` disabled. |
| Yes | Yes | No | - | **Physical Network**: Physical gateway dropping packets, or external server checking source IP (NAT failed?). |
| Yes | Yes | Yes | No | **Return Path**: `rp_filter` dropped the return packet, or `eth0` route missing causing loop. |
| Yes | Yes | Yes | Yes (but fail) | **OVN Port Security**: Unmatched Source IP. Packets leave `eth0` with External IP as source, but OVN drops them because they don't match Pod IP. |

**5. Isolation on Gateway Node (Sending Side):**
The packet leaves the Pod (seen in Pod tcpdump) but never appears on the Host Geneve interface.
**Root Cause found:** Host Kernel `rp_filter`.

*   **Logic:** The Host receives a packet from the Pod (via `br-int`) with Source IP `192.168.99.1`.
*   **Check:** The Host kernel looks up `192.168.99.1`. It expects that traffic to come from `br-ex` (Physical).
*   **Drop:** Since it came from `br-int` (Overlay), the Kernel thinks it's a spoofed packet and silent-drops it.

**A. Disable Host-Level RP_Filter (The "Nuclear" Option):**
Simply setting `all` to 0 might not be enough if the specific `veth` interface was created with `1`. Linux uses the MAX value of `all` and `interface` (or sometimes `conf` and `all` logic is complex).
We must disable it on **ALL veth interfaces** to be sure.

Run this script in the **Gateway Node Debug Shell**:
```bash
# 1. Disable on global/default/bridges
sysctl -w net.ipv4.conf.all.rp_filter=0
sysctl -w net.ipv4.conf.default.rp_filter=0
sysctl -w net.ipv4.conf.br-int.rp_filter=0
sysctl -w net.ipv4.conf.br-ex.rp_filter=0

# 2. Disable on ALL veth interfaces (one of these connects to your pod)
for dev in $(ls /sys/class/net/ | grep veth); do
  sysctl -w net.ipv4.conf.$dev.rp_filter=0
done

# 3. Disable on physical interfaces too
PHYS_INT=$(ip route show default | awk '/default/ {print $5}')
sysctl -w net.ipv4.conf.$PHYS_INT.rp_filter=0
```

> **Note on using Physical Interface vs br-ex:**
> You asked if using a physical port (e.g. `enp1s0`) is better than `br-ex`.
> *   **If `enp1s0` is part of `br-ex`:** You **cannot** use it directly for macvlan. You must use `br-ex`.
> *   **If you have a SPARE physical port:** Yes, moving the NAD to a spare `enp2s0` (not used by OpenShift) is cleaner and avoids OVS bridge issues. But if you only have one uplink, stick with `br-ex` and fix the `rp_filter`/offload settings.
