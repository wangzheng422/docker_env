# openshift 4.15 UPI in agent way, single node

OpenShift的安装方式很多了，现在又多了一种，agent based installer。最大的特点是，不需要额外的bootstrap节点了。这可是天大的好消息，因为，以前安装之前，和客户交流，客户总是不理解，为什么红帽说支持3节点部署，但是却要求提供4台服务器。也不能怪客户，按照一般的理解，之前红帽是不支持严格意义上的3节点部署，就因为有这个bootstrap. 现在好了，agent based installer是真正世俗意义上的支持3节点部署了。

从官方文档来看，能压缩掉bootstrap，是因为bootstrap相关的服务，都压缩到一个master节点上，并使用了assisted installer流程，来达到真正的3节点安装的。

- https://docs.openshift.com/container-platform/4.13/installing/installing_with_agent_based_installer/preparing-to-install-with-agent-based-installer.html

本文，就用agent based installer来装一个单节点的ocp集群。

```bash
# --- Configuration ---
VG_NAME="vgdata"
TARGET_DEVICE="vdb"
# --- End Configuration ---

echo "Starting to attach data disks to VMs (Robust Method)..."

# Outer loop for the demo number (01 and 02)
for demo_num in 01 02
do
  # Inner loop for the master number (01, 02, and 03)
  for master_num in 01 02 03
  do
    # Construct the VM name and the LV path from the loop variables
    VM_NAME="demo-${demo_num}-master-${master_num}"
    LV_PATH="/dev/${VG_NAME}/lv-${VM_NAME}-data"

    echo "-----------------------------------------------------"
    echo "Processing VM: ${VM_NAME}"

    # Safety check: Ensure the Logical Volume (block device) actually exists
    if [ -b "$LV_PATH" ]; then
      echo "Found LV: ${LV_PATH}. Attaching as ${TARGET_DEVICE}..."

      # Create a temporary file to hold the XML definition for our disk
      DISK_XML_FILE=$(mktemp)

      # Populate the XML file with the precise disk configuration.
      # This XML is the correct format that libvirt expects.
      cat << EOF > "$DISK_XML_FILE"
<disk type='block' device='disk'>
  <driver name='qemu' type='raw' discard='unmap'/>
  <source dev='${LV_PATH}'/>
  <target dev='${TARGET_DEVICE}' bus='virtio'/>
</disk>
EOF

      # Use attach-device with the correct XML file.
      # This is the most compatible and reliable method.
      virsh attach-device "${VM_NAME}" "${DISK_XML_FILE}" --persistent

      # Clean up the temporary file
      rm -f "$DISK_XML_FILE"

      echo "Successfully attached disk to ${VM_NAME}."
    else
      echo "WARNING: LV path ${LV_PATH} not found. Skipping attachment for ${VM_NAME}."
    fi
  done
done
```

### 第三步：配置NFS-Ganesha

NFS-Ganesha的配置文件 `/etc/ganesha/ganesha.conf` 功能非常强大，但默认配置很复杂。我们将从一个最小化的、清晰的配置开始。

1.  **备份默认配置文件**：

```bash

```

2.  **创建一个新的、简单的配置文件**：
    我们将配置NFS-Ganesha来导出一个本地目录 `/srv/ganesha-share`。

```bash
# Create a new configuration file using cat and a heredoc.
# Using <<'EOF' is safer as it prevents shell expansion of variables.
sudo tee /etc/ganesha/ganesha.conf << 'EOF'
# /etc/ganesha/ganesha.conf - Corrected and Improved Configuration
# This version uses EXPORT_DEFAULTS for cleaner configuration and adds comments.

LOG {
    COMPONENTS {
        ALL = INFO;
    }
    FACILITY {
        name = "file";
        destination = "/var/log/ganesha.log"; # Check this log for errors!
    }
}

NFS_CORE_PARAM {
    # 仅启用 NFSv4 协议。Ganesha 会自动协商客户端支持的最高子版本 (v4.0, v4.1, v4.2)。
    Protocols = 4;
}

# Define default settings for all exports to avoid repetition.
EXPORT_DEFAULTS {
    Access_Type = RW;
    Squash = No_Root_Squash;
    SecType = "sys";
    Protocols = 4;
    Clients = 0.0.0.0/0;
}

# EXPORT BLOCK - Defines a share for openshift-01
EXPORT {
    Export_Id = 10;
    Path = "/srv/nfs/openshift-01"; # Ensure this path exists and has correct permissions
    Pseudo = "/openshift-01"; # The path clients will see
    # Clients = "0.0.0.0/0"; # Allow access from any client
    FSAL {
        Name = VFS; # Use VFS for standard filesystems like XFS or ext4
    }
}

# EXPORT BLOCK - Defines a share for openshift-02
EXPORT {
    Export_Id = 20;
    Path = "/srv/nfs/openshift-02";
    Pseudo = "/openshift-02";
    # Clients = "0.0.0.0/0";
    FSAL {
        Name = VFS;
    }
}

# EXPORT BLOCK - Defines a share for static
EXPORT {
    Export_Id = 30;
    Path = "/srv/nfs/static";
    Pseudo = "/static";
    # Clients = "0.0.0.0/0";
    FSAL {
        Name = VFS;
    }
}
EOF
```

Optimize NFS Client Mount Options

Using `noatime`, `nodiratime`, and `actimeo=60` mount options on the client side can significantly improve performance.
- `noatime` and `nodiratime` reduce unnecessary writes to the NFS server by not updating file and directory access times.
- `actimeo=60` tells the client to cache file and directory attributes for 60 seconds, which reduces the number of network requests and can help alleviate lock contention.
