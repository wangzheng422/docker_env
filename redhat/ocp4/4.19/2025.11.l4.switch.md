# using L4 switch as ingress gateway.

normally, openshift 4.19 router pods needs a L7 switch infront to access traffic, and distrubute the traffic across the router pod, which is haproxy internally. but If CU only has L4 switch, and only can do L4 check, which is tcp alive check, when router pod migrate to another node, the app service will disrupte for a while.

what we plan to fix, is run a deamonset, the pod will run as sibling of router pod, it will check the router pod's health check endpoint (l7), and it selfe running in host network, and will open another tcp port(rest api is ok), if it check the router pod's health check endpoint fail, it will shutdown the rest api immediatly withouth wait any time.( this is very important, do not wait for existed connnection to finish ). the rest api will shutdown by default, only when the router pod's health check ok it will start.
