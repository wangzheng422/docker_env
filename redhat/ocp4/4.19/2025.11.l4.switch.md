# using L4 switch as ingress gateway.

normally, openshift 4.19 router pods needs a L7 switch infront to access traffic, and distrubute the traffic across the router pod, which is haproxy internally. but If CU only has L4 switch, and only can do L4 check, which is tcp alive check, when router pod migrate to another node, the app service will disrupte for a while.

what we plan to fix, is run a deamonset, the pod will run as sibling of router pod, it will check the router pod's health check endpoint (l7), and it selfe running in host network, and will open another tcp port(rest api is ok), if it check the router pod's health check endpoint fail, it will shutdown the rest api immediatly withouth wait any time.( this is very important, do not wait for existed connnection to finish ). the rest api will shutdown by default, only when the router pod's health check ok it will start.

So I need a demo, first, create a haproxy, with L7 check on the router pod, and start a service with 3 pod, and expose router, curl the route, migrate the router pod (delete it), and using ab to test the sucess rate (ab should not high pressure, just check seuccess rate, expected 100%)

then, switch the haproxy to L4 check on the router pod, do the same ab testing, and pod migate(route pod delete), expected some failed, success rate 95%.

now, create the python script for me, the logic is as above, and run the python script with standar redhat ubi python image, script injected in a configmap. and create deamon set, start the sibling pod, so we create a L4 checkpoint at 18898 with the same route pod node.

## run with L7 switch (haproxy simulation)

install haproxy locally

```bash
dnf install -y haproxy
```

configure it as L7 switch, which mean using L7 health check on router pod

```bash
tee /etc/haproxy/haproxy.cfg << EOF
global
  log stdout format raw local0
  maxconn 20000

defaults
  log     global
  mode    http
  option  httplog
  option  dontlognull
  timeout connect 1000
  timeout client  50000
  timeout server  50000

frontend http_front
  bind *:8080
  stats uri /haproxy?stats
  default_backend http_back

backend http_back
  balance roundrobin
  # --- L7 Health Check ---
  option httpchk GET /healthz/ready HTTP/1.0
  http-check expect status 200
  # Set default health check interval to 2 seconds (2000ms) for all servers
  default-server inter 2000
  # -----------------------
  server pod-1 192.168.99.23:1936 check
  server pod-2 192.168.99.24:1936 check
  server pod-3 192.168.99.25:1936 check
EOF

systemctl restart haproxy

```

run the pod

```bash
oc new-project l4-switch-demo

tee $BASE_DIR/data/install/route-l4-pod.yaml << EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-openshift
  namespace: l4-switch-demo
  labels:
    app: hello-openshift
spec:
  replicas: 3
  selector:
    matchLabels:
      app: hello-openshift
  template:
    metadata:
      labels:
        app: hello-openshift
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchExpressions:
              - key: app
                operator: In
                values:
                - hello-openshift
            topologyKey: "kubernetes.io/hostname"
      containers:
      - name: hello-openshift
        image: docker.io/openshift/hello-openshift
        env:
          - name: "RESPONSE"
            value: "Hello World!"
        ports:
        - containerPort: 8080
          protocol: TCP
        - containerPort: 8888
          protocol: TCP
---
apiVersion: v1
kind: Service
metadata:
  name: hello-openshift
  namespace: l4-switch-demo
  labels:
    app: hello-openshift
spec:
  ports:
  - name: 8080-tcp
    port: 8080
    protocol: TCP
    targetPort: 8080
  - name: 8888-tcp
    port: 8888
    protocol: TCP
    targetPort: 8888
  selector:
    app: hello-openshift
  type: ClusterIP
---
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: hello-openshift
  namespace: l4-switch-demo
  labels:
    app: hello-openshift
spec:
  to:
    kind: Service
    name: hello-openshift
    weight: 100
  port:
    targetPort: 8080-tcp
  wildcardPolicy: None
EOF

oc apply -f $BASE_DIR/data/install/route-l4-pod.yaml

```

do the ab testing, and delete router pod

```bash

ROUTE_HOST=$(oc get route hello-openshift -n l4-switch-demo -o jsonpath='{.spec.host}')


ab -c 10 -H "Host: ${ROUTE_HOST}" http://localhost:8080/ 

# during the ab, delete a router pod
router_pod_to_delete=$(oc get pods -n openshift-ingress -l ingresscontroller.operator.openshift.io/deployment-ingress-controller=default -o jsonpath='{.items[0].metadata.name}')
oc delete pod ${router_pod_to_delete} -n openshift-ingress --grace-period=0


```
